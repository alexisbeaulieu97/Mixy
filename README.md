# Mixy

Mixy is a Python CLI for generating a project from one or more template sources.

It combines ordered template sources into a single output directory, resolves variables from
multiple inputs, renders Jinja-based templates, and applies deterministic merge rules so
generation stays predictable.

## What Mixy does

- Generates a project from a YAML config file.
- Supports local directory sources and Git sources today.
- Renders file contents and path names with Jinja.
- Resolves variables from defaults, config values, environment, vars files, per-source values,
  CLI overrides, and prompts.
- Detects merge conflicts before writing files.
- Lets you preview the result with `inspect` and `generate --dry-run`.

## Install

Mixy is currently set up to run from a source checkout.

With `uv`:

```bash
uv sync
uv run mixy --help
```

With `pip`:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .
mixy --help
```

Requirements:

- Python 3.11+
- `pygit2` for `git` sources

## Quickstart

Create a small template directory:

```text
template/
  README.md.j2
  src/
    {{ module_name }}.py.j2
```

Example template files:

```md
<!-- template/README.md.j2 -->
# {{ project_name }}

Generated by Mixy.
```

```python
# template/src/{{ module_name }}.py.j2
def main() -> None:
    print("Hello from {{ project_name }}")
```

Create `mixy.yml`:

```yaml
version: "1"
name: example-app
description: Minimal Mixy project

variables:
  project_name:
    type: str
    default: hello-app
    required: false
  module_name:
    type: str
    default: hello_app
    required: false

sources:
  - id: base
    source:
      type: local_dir
      path: ./template

output:
  path: ./generated
```

Preview the plan:

```bash
mixy inspect mixy.yml
mixy generate mixy.yml --dry-run
```

Generate files:

```bash
mixy generate mixy.yml --var project_name=my-app --var module_name=my_app
```

Expected output:

```text
generated/
  README.md
  src/
    my_app.py
```

If you are running from a source checkout with `uv`, prefix commands with `uv run`.

## Example config

This example shows multiple sources, project-level values, per-source values, and a conflict
policy:

```yaml
version: "1"
name: team-service
description: Service scaffold assembled from multiple templates

variables:
  project_name:
    type: str
    description: Display name for the generated project
    default: team-service
    required: false
  module_name:
    type: str
    default: team_service
    required: false
  python_version:
    type: str
    default: "3.12"
    required: false
    choices: ["3.11", "3.12", "3.13"]

values:
  python_version: "3.12"

sources:
  - id: base
    source:
      type: local_dir
      path: ./templates/base

  - id: ci
    values:
      python_version: "3.13"
    source:
      type: local_dir
      path: ./templates/ci

  - id: upstream
    source:
      type: git
      url: https://github.com/example/templates.git
      ref: main
      subpath: python-service

output:
  path: ./out/team-service
  conflict_policy: overwrite
```

Generate with overrides:

```bash
mixy generate mixy.yml \
  --vars-file team-values.yml \
  --var project_name=payments-api \
  --var module_name=payments_api
```

## Commands

```text
mixy generate CONFIG_PATH
mixy validate CONFIG_PATH
mixy inspect CONFIG_PATH
mixy cache list
mixy cache clear [--url URL]
mixy version
```

Global options:

- `--log-level [debug|info|warning|error]`
- `--quiet`

## Current limitations

- `local_dir` and `git` are the working source providers in the current generation pipeline.
- Git sources use the `pygit2` runtime rather than a shell `git` executable on `PATH`.
- There is no published docs site yet; the documentation lives in Markdown under `docs/`.
